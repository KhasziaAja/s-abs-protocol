# 法務清算フレームワークおよび段階的オンボーディングフロー

[*English Version (03_legal_onboarding.en.md)*](./03_legal_onboarding.en.md)

> **文書ステータス**: RFC ドラフト v1.0（Public Tier 1 仕様）
>
> **対象範囲**: 法務構造（*Lex Mercatoria* / 国際商慣習法）、2社間事前損害賠償予定約定タームシート、国際商事仲裁ルーティング、およびコールドスタート摩擦を解消するための二段階オンボーディング導線。

## 1. 制度的ポジショニング：デジタル *Lex Mercatoria*（私的秩序）

主権国家の国境を越えて稼働しつつ、規制上の「無免許保険業者」としての分類を回避するため、S-ABS Protocol は *Lex Mercatoria*（商人が自律的に形成する私的商慣習法）の伝統に則った **決定論的商取引検証SaaS** として法的に設計されている。

### 1.1 役割の構造的分離

| エンティティ / 役割 | 法的機能 | 規制上の境界線 |
| :--- | :--- | :--- |
| **S-ABS プロトコル運営主体** | 客観的な状態検証エンジンおよび暗号学的証明の提供者。 | **非保険業者:** 保険料のプーリング、リスクの引受け、相手方債務の肩代わり、または裁量的な損害査定を一切行わない。 |
| **預託企業 ($i$)** | 自己管理下の **利回り透過型エスクロー（Yield-Bearing Escrow）** にプログラマブル質権付きで準備金を配置する資産保有者。 | 客観的な契約違反が検証されない限り、担保の100%の受益権および原資産の運用利回りを保持し続ける。 |
| **取引相手 ($j$)** | `Dynamic Credit Pass` および `Threshold ZKP` の保証に依拠する商取引パートナー。 | エンティティ $i$ と直接の2社間商契約を締結し、トリガー成就が検証された際に執行可能な質権請求権を保有する。 |
| **国際仲裁機関** | 2社間契約で指定された独立した国際仲裁廷（例：SIAC、ICC）。 | **ニューヨーク条約（1958年）** に基づき、170以上の法域で執行可能な法的最終判断（仲裁判断）を提供する。 |

## 2. モデル・タームシート：2社間事前損害賠償予定約定

S-ABS を介して執行されるすべての `Tier 2 (Full Escrow)` コミットメントは、基本取引契約（MSA）または供給契約に付随する以下の標準特約条項によって規律される。

```text
================================================================================
モデル特約条項：2社間事前損害賠償予定約定およびプログラマブル・エスクロー合意書
================================================================================

1. 本合意の性質（非保険性の確認）
   両当事者は、本合意が一般契約法に基づく事前損害賠償予定（Liquidated Damages）
   に関する2社間の商事特約を構成することを明示的に確認する。S-ABS Protocol および
   そのオラクル運営者は、いかなる意味においても保険者、保証人、または受託リスク負担者
   として行動するものではない。

2. 確定自前補償枠（CAP）および動的質権
   債務者（エンティティ i）は、指定された利回り透過型エスクロー内に、コミットされた補償枠
   （USD [金額]）以上の適格バッファー担保を維持することに同意する。債権者（エンティティ j）は、
   決済期間中、当該担保に対する第一順位のプログラマブル担保権（質権）を付与される。

3. 客観的トリガー条件および自動執行
   指定されたオラクル定足数により、客観的債務不履行事由（別紙Aに定義：例として検証済みの
   納入遅延、SLA稼働率違反、または倒産手続開始申立て）が発生した旨の暗号学的証明がなされた
   場合、エスクロー・スマートコントラクトはコミットされた補償枠を上限として決定論的な支払いを
   自動執行する。

4. 非関連性グラフ検証および共謀防止セーフガード
   自動グラフ・テレメトリにより、債務者と債権者の間に未開示の実質的支配者（UBO）の重複または
   循環的な資金相関が検知された場合、即時一括支払いは停止され、第三者監査を伴うマイルストーン型
   段階検証プロセスへと移行する。

5. 紛争解決および仲裁判断の終局性（ニューヨーク条約）
   オラクルの正確性またはトリガーの有効性に関するいかなる紛争も、[シンガポール / チューリッヒ]
   における [SIAC / ICC] の迅速仲裁規則に基づく仲裁により終局的に解決されるものとする。
   プロトコルによって生成された暗号学的 ZKP レシートおよび来歴家系図ルートは、一応の証拠
   （prima facie evidence）として証拠能力を有するものとする。
================================================================================
```

## 3. コールドスタート問題の解消：段階的オンボーディングフロー

ネットワークの初期段階において、企業に多国籍法域のRWAを即座に72時間以上ロックするよう要求すると、導入時の摩擦が極めて高くなる。S-ABS はこれを **二段階のプログレッシブ・オンボーディング導線** によって解決する。

```text
[ PHASE 1: ロックなし・テレメトリ認証 (Entry Tier) ]
  ├─ 導入手順: 読み取り専用 Open Banking / ERP API ＋ 来歴オラクル接続
  ├─ 資本ロック: $0 (運転資金の拘束ゼロ / サブスクリプション費用ゼロ)
  ├─ 出力物: 軽量版 Dynamic Credit Pass (リアルタイム支払能力 ＆ 失敗ログスコア)
  └─ 提供価値: 静的な信用調査レポートを代替し、日常取引の監査摩擦を低減
                                     │
                                     ▼ (大型契約・信用状 L/C コスト削減を契機に転換)
[ PHASE 2: プログラマブル・エスクロー ＆ フル補償枠 (Institutional Tier) ]
  ├─ 導入手順: 多国籍RWA / 国債の割当て ＋ 動的質権設定
  ├─ 資本ロック: 最低72時間のプログラマブル・ロック (運用利回りは100%還元)
  ├─ 出力物: Threshold ZKP ("YES/NO" 補償枠証明) ＋ 再保険数理フィード
  └─ 提供価値: 銀行のL/C発行手数料 (1.5%〜3.0%) を削減し、超過損害再保険の割引を獲得
```

### 3.1 Phase 1：ロックなし・テレメトリ認証 (`TIER_1_TELEMETRY`)

* **導入摩擦の最小化:** 資本のロックアップは一切不要。読み取り専用のAPIキーを介して24時間以内に統合が完了する。
* **メカニズム:** 企業は銀行・ERPの読み取りフィードを接続し、運用テレメトリを **暗号学的来歴オラクル（Cryptographic Provenance Oracle）** にバインドする。S-ABS はリアルタイムの **内部リスク吸収能力（Absorptive Capacity）** スコアを算出する（テレメトリの供給が停止した場合は標準の **自然減衰：Demurrage** が適用される）。
* **実務上の効用:** 国内のB2Bサプライチェーンにおいて、現金を拘束することなく財務の健全性とエンジニアリングの透明性を証明するために利用される。

### 3.2 Phase 2：プログラマブル・エスクローおよびフル補償枠 (`TIER_2_FULL_ESCROW`)

* **転換トリガー:** Phase 1 導入企業が、信用状（L/C）、履行保証ボンド、または担保預託が要求されるクロスボーダー契約、インフラプロジェクト、または高額SLAに入札するタイミング。
* **メカニズム:** 返還されない銀行のL/C発行手数料（1.5%〜3.0%）を支払う代わりに、企業は保有する国債やトークン化された地金（RWA）を **利回り透過型エスクロー** に配置する。
* **経済的帰結:** 企業は国債等の運用利回りを100%保持したまま、`Threshold ZKP` を通じて取引相手の与信要件を満たし、さらに検証済みの確定自前補償枠（$\text{Cap}$）の下限値を **再保険数理フィード（Reinsurance Actuarial Feeds）** へ出力することで、割引された超過損害再保険（XoL）のテールリスク補償を獲得する。

## 4. 紛争ライフサイクルと Exit Queue（退出待機列）メカニクス

1. **正常完了:** 契約違反なく契約期間が満了した場合、動的質権は自動的に解除される。担保資産は一斉取り付け（流動性ラン）を防ぐため、ランダム化されたクールダウン遅延（ジッター）を伴う **非対称 Exit Queue** を経て、制約のない流動性へと戻る。
2. **客観的違反トリガー:** 保証金を預託した検証ノード定足数によって契約違反が証明された場合、資金は取引相手の決済アドレスへ自動送金される。異議申立期間内に正式な仲裁申立てが行われた場合、紛争対象資金は仲裁判断が下されるまで中立的な `Dispute Hold`（紛争保留）状態に置かれる。

*(注：具体的な Exit Queue のジッター確率分布、異議申立期間の長さ、および検証ノードのスラッシング保証金比率は `[Foundry Core / Proprietary Calibration]` 内に隔離されている。)*
